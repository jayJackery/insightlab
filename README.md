# InsightLab · GitHub Pages 网页版

无需安装、无需登录。打开网站，点击“服务配置”，填写自己的DeepSeek密钥并“应用到本次页面”，然后提交需求、确认研究计划、开始研究。

## 发布到 GitHub Pages

1. 在 `jayJackery` 账号下创建用于本项目的仓库，例如 `insightlab`。只上传本发布包的内容，不上传个人工作目录或data。
2. 把发布包**解压后的全部文件和目录**放到仓库根目录，包含 `index.html`、`src`、`public`、`assets`、`vendor`、`.nojekyll`、`.github` 等；不要只上传ZIP。
3. 最简单的发布：仓库 Settings → Pages → Source 选择 **Deploy from a branch**，分支选择 **main / (root)**，保存。GitHub显示的网址通常为 `https://jayJackery.github.io/insightlab/`，以实际发布结果为准。
4. 也可把 Source 设为 **GitHub Actions**，使用包内 `.github/workflows/pages.yml` 工作流部署。
5. 确认GitHub显示部署成功，再把网址发给同事。上传文件不代表已经成功上线。

## 使用和数据

- 密钥仅存在当前页面内存，不写浏览器数据库、报告备份或GitHub。刷新/关闭后需要重新填写；不要把公共密钥写进程序。
- 报告与阶段检查点保存在当前浏览器、当前网站路径对应的IndexedDB。不同浏览器/电脑不会自动同步。清除网站数据或更换发布路径前，点击“备份报告”。
- 备份JSON不包含密钥，可在另一台电脑“导入备份”。导入创建独立记录，不覆盖旧任务，并标为尚未按当前规则验收。
- 同一工作区仅一个标签页可写；其他标签页只读，关闭原页后刷新即可接管。
- 关闭/刷新、电脑休眠可能中断研究；重新打开后填写本页密钥，再从失败阶段重试，不会自动重新收费执行。
- 浏览器不允许保存、空间不足或网络/跨域失败时，按页面提示处理。不要关闭浏览器安全保护来绕过错误。

## 研究与费用

保留原始问题、同档竞品筛选、公开检索与补查、证据核验、技术章节、最终整篇审查；不通过时只提供待核验稿。“检测连接”会调用模型和搜索，可能收费。密钥所属账号承担API费用，GitHub仅托管静态程序，不执行研究。

部门规格库优先实时读取；网络受限时使用有抓取日期的公开随包快照，保留地区、产品原复核日期与整理来源，不冒充官网实时核验。

支持按章节/技术主题导出Word。格式与事实质量分别验收；草稿不等于正式报告。

## 更新

维护人重新构建并上传同一仓库路径，部署成功后同事重新打开网页即可使用新版。无需安装运行环境。研究中请等待结束再刷新。不要上传自己的报告备份、密钥、`data` 或实际研究数据库。

## 开发构建

开发工作区运行 `node scripts/refresh-browser-catalog.mjs` 刷新公开快照，再运行 `node scripts/build-pages.mjs`。构建只收集浏览器可达模块、样式和公开规格数据，生成 `artifacts/InsightLab-GitHub-Pages.zip`。构建依赖hash.js与pako，构建机可通过 `INSIGHTLAB_BUILD_NODE_MODULES` 指定依赖目录；网站使用者不需要安装Node或任何依赖。
